# RE-4: аудио-путь ES8311 на плате (2026-09-09)

Физическая приёмка полного аудио-пути по шагам 1.4–1.9 плана
[`rockcast-device-plan.md`](rockcast-device-plan.md): общий владелец I2C1,
ES8311+I2S через `esp_codec_dev` 1.6.2, детерминированный тон, метрики
захвата микрофона и 60-секундный конкурентный loopback с измерением
ресурсов. Протокол устройства не расширялся — плеер это RE-5.

Код: `main/board_bus.{c,h}` (единственный владелец шины), `main/audio_bsp.{c,h}`
(изолированный bring-up модуль по образцу `display_bsp.c`). Спайк-заглушка
RE-3 `main/audio_spike.c` и её линкер-флаг `-u rock_re3_component_roots`
удалены: `esp_codec_dev` теперь линкуется реальными вызовами.

## Железо и wiring

| Сигнал | Пин | Источник |
| --- | --- | --- |
| ES8311 I2C (общая шина с GT911) | SDA GPIO7, SCL GPIO8, I2C1 | board-hardware.md |
| ES8311 адрес | 7-бит 0x18 (= `ES8311_CODEC_DEFAULT_ADDR` 0x30 в 8-бит форме esp_codec_dev) | » |
| I2S BCLK / MCLK / WS | GPIO12 / GPIO13 / GPIO10 | » |
| I2S DOUT (спикер, DAC) | GPIO9 | » |
| I2S DSIN (микрофон, ADC) | GPIO48 | » |
| PA enable (active high) | GPIO11 | » |

Конфигурация: I2S0 master, full-duplex пара каналов, std Philips, MCLK
256×fs = 4.096 МГц, 16 бит, DMA 6 дескрипторов × 480 кадров (глубина 180 мс),
`auto_clear_after_cb`. ES8311: `WORK_MODE_BOTH`, slave, внешний MCLK,
аппаратный gain из пары напряжений PA 5.0 В / DAC 3.3 В (как в рабочем
вендор-демо xiaozhi для этой платы). Выход: vol 70, вход: gain +30 дБ.

## Единый владелец I2C1

`rock_i2c1_bus_acquire()` (main/board_bus.c) создаёт шину I2C1 один раз при
старте из `app_main`; GT911 (через `esp_lcd_new_panel_io_i2c`) и ES8311
(через `audio_codec_new_i2c_ctrl` c `bus_handle` и `clock_speed_hz=400000`)
подключаются к одному и тому же handle. Вторая шина не создаётся. Отдельный
мьютекс не нужен: новый I2C master-драйвер сериализует транзакции устройств
одной шины внутренним `bus_lock_mux` (проверено по исходникам IDF 6.1).
GT911 продолжает работать без перезагрузки кода дисплея — см. проверку ниже.

## Управление PA

PA (GPIO11) управляется вручную из `audio_bsp.c` (`pa_pin = -1` в конфиге
ES8311, чтобы драйвер кодека не трогал пин): вывод сконфигурирован
push-pull с pull-down, по умолчанию 0, включается только перед реальным
выводом сэмплов и выключается после дрейна DMA-очереди (глубина 180 мс +
запас). После всей последовательности кодек закрывается, PA выключен.

## Последовательность и результаты (прошивка 2026-09-09, COM6, без erase_flash)

Один прогон = 3 с тон → 10 с захват → 60 с конкурентный loopback. Все числа
ниже из финального прогона; соседние прогоны дали согласующиеся значения.

### Playback: тон

| Параметр | Значение |
| --- | --- |
| Форма | синус 440 Гц, 16 бит mono 16000 Гц, 48000 сэмплов (3.0 с) |
| Огибающая | fade-in ~30 мс, fade-out ~300 мс (плавный, без щелчка) |
| Амплитуда | 16000 (~-6.2 dBFS), громкость кодека 70 |
| Ошибки записи | 0 |
| Макс. интервал между записями | 70.8 мс при глубине DMA 180 мс — underrun нет (порог warn 90 мс, definite 180 мс) |
| PA | включён только на время вывода + дрейн |

Владелец слышит тон из динамика при каждой загрузке (однократный 3-секундный
сигнал ~1.5 с после старта).

### Capture: микрофон

| Метрика | Значение |
| --- | --- |
| Запрошено / получено | 16 бит mono 16 кГц / ровно 160000 сэмплов (10.0 с) |
| **Фактический wire-формат** | **16-bit mono int16 — совпадает с запросом** (детекция по соотношению чётных/нечётных лейн int16 в трёх чанках, голосование; гипотеза «32-битный стандартный I2S после ES8311» не подтвердилась) |
| Пик | -32.2 dBFS (469…806 отсчётов по прогонам) |
| RMS | -48…-50 dBFS (тихая комната) |
| Шумовой пол (тихое 1-с окно) | -56.0 dBFS |
| Клиппинг (\|s\|>=32700) | 0 |
| Ошибки чтения | 0 |

### Конкурентность: 60 с loopback (LVGL + GT911 + ESP-Hosted Wi-Fi скан активны)

Непрерывный тон 440 Гц (амп. 12000) в динамик + непрерывный захват
микрофона двумя задачами (`rock_au_out`, `rock_au_in`, приоритет 5),
мониторинг из третьей задачи каждые 10 с.

| Метрика | Значение |
| --- | --- |
| TX underrun (warn/definite) | 0 / 0; макс. интервал между записями 22.4 мс (глубина DMA 180 мс) |
| RX overrun (DMA queue overflow) | 8 за 60 с загруженного окна (~0.13% от ~1920 дескрипторов; отдельные выпадения при пиках Wi-Fi-скан/LVGL) |
| Ошибки read/write | 0 / 0 |
| CPU baseline (без аудиопотоков) | cpu0 4%, cpu1 0% |
| CPU под нагрузкой | cpu0 18–21%, cpu1 0% |
| Свободная internal RAM | стабильно ~287 КБ (мин. 286 907 Б); наибольший свободный блок 204 800 Б |
| Свободная PSRAM | 32 683 284 Б, без изменений за весь цикл |
| Мин. остаток стека | writer 3464 Б / 4096, reader 3484 Б / 4096, монитор 4732 Б / 6144 |
| Task watchdog | 0 срабатываний за весь цикл (проверка idle-задач обоих ядер включена) |
| GT911 через общий I2C1 | 6/6 успешных проб (чтение product-id «911») при полной нагрузке |
| Wi-Fi (ESP-Hosted 3.0.7) | скан продолжался весь цикл (12 сканов за 150 с лога, 8–10 точек) |
| Акустическая петля | микрофон при играющем динамике: RMS +2.9 дБ и пик -21.7 dBFS против -32.2 dBFS фона (в другом прогоне пик до -14.7 dBFS — уровень связи зависит от ориентации платы) |
| Финал | кодек закрыт, PA off, rc=0; ошибок уровня `E (` в логе нет |

Замер CPU — idle-хуками FreeRTOS per-core: хук возвращает `false`, чтобы
диспетчер не уходил в WFI на время окна измерения (иначе хук вызывается раз
в тик и весь тик выглядит «занятым»); гэпы между вызовами >250 мкс считаются
занятым временем. Хуки снимаются после измерения.

## Оговорки и открытые вопросы

- **RX queue overflow (8 за 60 с).** Читатель loopback-а читает блоками по
  100 мс с нулевым запасом относительно скорости DMA; при совместных пиках
  (скан + LVGL) очередь из 6 дескрипторов переполняется и теряет данные без
  ошибки чтения. Для RE-5 нужен честный ring-buffer пайплайн (читатель
  меньшими блоками и/или приоритет/пин на cpu1); счётчик `on_recv_q_ovf`
  обязателен в метриках плеера.
- **Всё аудио на cpu0.** Задачи без affinity: планировщик держит аудио,
  LVGL, Wi-Fi на cpu0 (21%), cpu1 простаивает (0%). RE-5 стоит запинить
  аудиозадачи на cpu1 — половина ресурса сейчас не используется.
- **Акустическая связь микрофон↔динамик** варьирует между прогонами
  (пик от -14.7 до -21.7 dBFS при одинаковом выводе). Для AEC (RE-8)
  замерить на реальном корпусе/расположении.
- **Уровень захвата при +30 dB gain**: фон -56 dBFS, пик комнаты -32 dBFS —
  запас до клиппинга большой; для голосового пути (RE-7/8) усиление можно
  поднять (ES8311 PGA до ~42 дБ), но проверять клиппинг возле динамика.
- Тон и захват запускаются автоматически при каждом старте
  (`rock_audio_bringup_start()` в `app_main`) — это bring-up код; RE-5
  заменяет его на плеер с командным управлением.
- Сброс платы из скрипта: у USB-Serial/JTAG свой reset (esptool
  `USBJTAGSerialReset` — чип перечисляется заново), обычный RTS-импульс не
  работает. Использовалась двухфазная последовательность
  (bootloader-reset → hard reset) с переоткрытием порта.
